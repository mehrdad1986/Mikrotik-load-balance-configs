RouterOS 7 Triple-WAN PCC

Triple-WAN PCC Load Balancing + Failover

MikroTik RouterOS 7 configuration for three uplinks: ether1, ether2, and lte1, with LAN on ether4 and ether5.

WAN1 ether1 — 192.168.2.100/24
Gateway: 192.168.2.1
WAN2 ether2 — 192.168.0.100/24
Gateway: 192.168.0.1
WAN3 LTE lte1 — 10.42.182.53/24
Gateway: 10.42.182.70
LAN ether4 + ether5
Bridge: bridge-LAN
1

Phase 1: Backup Before Applying

Always backup your current RouterOS configuration before applying a new PCC setup.

/system backup save name=before-triple-wan-pcc
/export file=before-triple-wan-pcc-export
Important: Do not apply this blindly on a production router. Test step by step, especially if you are connected remotely.
2

Phase 2: System Identity and Interface Names

Rename Ethernet interfaces and prepare a bridge for LAN ports ether4 and ether5.

/system identity set name=Triple-WAN-PCC-Router

/interface ethernet
set [find default-name=ether1] name=ether1 comment="WAN1 - 192.168.2.100/24"
set [find default-name=ether2] name=ether2 comment="WAN2 - 192.168.0.100/24"
set [find default-name=ether4] name=ether4 comment="LAN Port 1"
set [find default-name=ether5] name=ether5 comment="LAN Port 2"
/interface bridge
add name=bridge-LAN protocol-mode=rstp comment="LAN bridge for ether4 and ether5"

/interface bridge port
add bridge=bridge-LAN interface=ether4
add bridge=bridge-LAN interface=ether5
Why: LAN traffic should enter the PCC rules through one logical interface, so ether4 and ether5 are placed inside bridge-LAN.
3

Phase 3: IP Address Configuration

Assign your WAN and LAN IP addresses.

/ip address
add address=192.168.2.100/24 interface=ether1 comment="WAN1 IP"
add address=192.168.0.100/24 interface=ether2 comment="WAN2 IP"
add address=10.42.182.53/24 interface=lte1 comment="WAN3 LTE IP"
add address=10.10.10.1/24 interface=bridge-LAN comment="LAN Gateway - CHANGE IF NEEDED"
LAN subnet note: I used 10.10.10.1/24 for LAN because you did not specify the LAN IP range. Change it to your real LAN subnet if required.
4

Phase 4: RouterOS 7 Routing Tables

RouterOS 7 uses named routing tables for policy routing.

/routing table
add name=to-WAN1 fib
add name=to-WAN2 fib
add name=to-WAN3 fib
Why: PCC will mark traffic with to-WAN1, to-WAN2, or to-WAN3. These routing tables must exist before policy routes are used.
5

Phase 5: Main Default Routes and Failover

These routes are used by normal unmarked router traffic and as general failover defaults.

/ip route
add dst-address=0.0.0.0/0 gateway=192.168.2.1 distance=1 check-gateway=ping comment="Main default via WAN1"
add dst-address=0.0.0.0/0 gateway=192.168.0.1 distance=2 check-gateway=ping comment="Backup default via WAN2"
add dst-address=0.0.0.0/0 gateway=10.42.182.70 distance=3 check-gateway=ping comment="Backup default via WAN3 LTE"
Priority Interface Gateway Distance
Primary ether1 192.168.2.1 1
Secondary ether2 192.168.0.1 2
Third / LTE lte1 10.42.182.70 3
6

Phase 6: PCC Connection Marking

Split LAN connections into three PCC buckets: WAN1, WAN2, and WAN3.

/ip firewall mangle
add chain=prerouting connection-state=established,related action=accept comment="Accept established/related"

add chain=prerouting in-interface=bridge-LAN connection-mark=no-mark \
    per-connection-classifier=both-addresses-and-ports:3/0 \
    action=mark-connection new-connection-mark=WAN1-conn passthrough=yes \
    comment="PCC bucket 0 to WAN1"

add chain=prerouting in-interface=bridge-LAN connection-mark=no-mark \
    per-connection-classifier=both-addresses-and-ports:3/1 \
    action=mark-connection new-connection-mark=WAN2-conn passthrough=yes \
    comment="PCC bucket 1 to WAN2"

add chain=prerouting in-interface=bridge-LAN connection-mark=no-mark \
    per-connection-classifier=both-addresses-and-ports:3/2 \
    action=mark-connection new-connection-mark=WAN3-conn passthrough=yes \
    comment="PCC bucket 2 to WAN3 LTE"
Why: :3/0, :3/1, and :3/2 divide new LAN connections into three PCC groups.
7

Phase 7: Routing Marking

Apply routing marks based on the connection marks created by PCC.

/ip firewall mangle
add chain=prerouting in-interface=bridge-LAN connection-mark=WAN1-conn \
    action=mark-routing new-routing-mark=to-WAN1 passthrough=no \
    comment="Route marked WAN1 connections via table to-WAN1"

add chain=prerouting in-interface=bridge-LAN connection-mark=WAN2-conn \
    action=mark-routing new-routing-mark=to-WAN2 passthrough=no \
    comment="Route marked WAN2 connections via table to-WAN2"

add chain=prerouting in-interface=bridge-LAN connection-mark=WAN3-conn \
    action=mark-routing new-routing-mark=to-WAN3 passthrough=no \
    comment="Route marked WAN3 connections via table to-WAN3"
Why: Connection marks classify traffic. Routing marks force that traffic to use the correct RouterOS 7 routing table.
8

Phase 8: Router-Originated Traffic Marking

Optional PCC for traffic generated by the router itself, such as DNS, NTP, update checks, or pings.

/ip firewall mangle
add chain=output connection-mark=no-mark \
    per-connection-classifier=both-addresses-and-ports:3/0 \
    action=mark-connection new-connection-mark=WAN1-conn passthrough=yes \
    comment="Router output PCC bucket 0 to WAN1"

add chain=output connection-mark=no-mark \
    per-connection-classifier=both-addresses-and-ports:3/1 \
    action=mark-connection new-connection-mark=WAN2-conn passthrough=yes \
    comment="Router output PCC bucket 1 to WAN2"

add chain=output connection-mark=no-mark \
    per-connection-classifier=both-addresses-and-ports:3/2 \
    action=mark-connection new-connection-mark=WAN3-conn passthrough=yes \
    comment="Router output PCC bucket 2 to WAN3"

add chain=output connection-mark=WAN1-conn \
    action=mark-routing new-routing-mark=to-WAN1 passthrough=no

add chain=output connection-mark=WAN2-conn \
    action=mark-routing new-routing-mark=to-WAN2 passthrough=no

add chain=output connection-mark=WAN3-conn \
    action=mark-routing new-routing-mark=to-WAN3 passthrough=no
Tip: If you want the router itself to always use WAN1 first, you can skip this phase.
9

Phase 9: Policy Routes for PCC Tables

Each PCC table gets its preferred WAN plus fallback routes.

/ip route
add dst-address=0.0.0.0/0 gateway=192.168.2.1 routing-table=to-WAN1 distance=1 check-gateway=ping comment="to-WAN1 primary via WAN1"
add dst-address=0.0.0.0/0 gateway=192.168.0.1 routing-table=to-WAN1 distance=2 check-gateway=ping comment="to-WAN1 fallback via WAN2"
add dst-address=0.0.0.0/0 gateway=10.42.182.70 routing-table=to-WAN1 distance=3 check-gateway=ping comment="to-WAN1 fallback via WAN3 LTE"

add dst-address=0.0.0.0/0 gateway=192.168.0.1 routing-table=to-WAN2 distance=1 check-gateway=ping comment="to-WAN2 primary via WAN2"
add dst-address=0.0.0.0/0 gateway=192.168.2.1 routing-table=to-WAN2 distance=2 check-gateway=ping comment="to-WAN2 fallback via WAN1"
add dst-address=0.0.0.0/0 gateway=10.42.182.70 routing-table=to-WAN2 distance=3 check-gateway=ping comment="to-WAN2 fallback via WAN3 LTE"

add dst-address=0.0.0.0/0 gateway=10.42.182.70 routing-table=to-WAN3 distance=1 check-gateway=ping comment="to-WAN3 primary via WAN3 LTE"
add dst-address=0.0.0.0/0 gateway=192.168.2.1 routing-table=to-WAN3 distance=2 check-gateway=ping comment="to-WAN3 fallback via WAN1"
add dst-address=0.0.0.0/0 gateway=192.168.0.1 routing-table=to-WAN3 distance=3 check-gateway=ping comment="to-WAN3 fallback via WAN2"
Why: If a WAN fails, traffic already marked for that WAN still has fallback paths inside the same routing table.
10

Phase 10: NAT Masquerade

Add separate masquerade rules for each outgoing WAN interface.

/ip firewall nat
add chain=srcnat out-interface=ether1 action=masquerade comment="NAT via WAN1"
add chain=srcnat out-interface=ether2 action=masquerade comment="NAT via WAN2"
add chain=srcnat out-interface=lte1 action=masquerade comment="NAT via WAN3 LTE"
Important: Each WAN must have its own NAT rule, otherwise PCC-routed traffic may leave with the wrong source address.
11

Phase 11: DNS

Enable DNS forwarding for LAN clients.

/ip dns
set servers=1.1.1.1,8.8.8.8 allow-remote-requests=yes
12

Phase 12: Optional DHCP Server for LAN

Use this only if your MikroTik should provide DHCP to LAN clients.

/ip pool
add name=LAN-pool ranges=10.10.10.100-10.10.10.250

/ip dhcp-server
add name=LAN-DHCP interface=bridge-LAN address-pool=LAN-pool disabled=no

/ip dhcp-server network
add address=10.10.10.0/24 gateway=10.10.10.1 dns-server=10.10.10.1,1.1.1.1
Change if needed: This DHCP block matches the example LAN subnet 10.10.10.0/24.
13

Phase 13: Netwatch Fast Failover

Clear existing connections when a WAN gateway becomes unreachable.

/tool netwatch
add host=192.168.2.1 interval=5s timeout=2s \
    down-script="/ip firewall connection remove [find connection-mark=WAN1-conn]" \
    comment="Monitor WAN1 gateway"

add host=192.168.0.1 interval=5s timeout=2s \
    down-script="/ip firewall connection remove [find connection-mark=WAN2-conn]" \
    comment="Monitor WAN2 gateway"

add host=10.42.182.70 interval=5s timeout=2s \
    down-script="/ip firewall connection remove [find connection-mark=WAN3-conn]" \
    comment="Monitor WAN3 LTE gateway"
Tip: Gateway monitoring checks only the next hop. For stronger internet-health checking, you can later replace or extend this with recursive routes to public targets.
